# 网页后台接口契约（第五阶段冻结）

本文件冻结 `web_dashboard` 与机器人端之间的数据契约，供双方联调核对。

标注说明：

- ✅ **已实现**：网页端已实现并有自动化测试覆盖（`tests/`）。
- 🔗 **网页端约定**：网页端已按此语义实现，但机器人端**尚未实现**，字段值由模拟工具或未来机器人端提供。
- ⏳ **待机器人端确认**：字段本身仍是建议，机器人端确认前不得视为已实现。

> 机器人端目前只确认了 `/fire_inspection/state`、`/fire_inspection/control`、
> `/fire_inspection/poi_result` 三个话题/服务相关字段（见 `接口契约冻结表.md`）。
> 本文件中标 🔗 / ⏳ 的内容均为网页侧建议，**不代表机器人已经支持**。

---

## 1. 机器人连接状态

来源：`GET /api/health`、`GET /api/status` 中的 `robot` 字段；由 ROS 适配层提供。

| 字段 | 类型 | 语义 | 状态 |
| --- | --- | --- | --- |
| `online` | bool | 只有 Bridge 返回 `online=true`（rclpy 就绪且控制服务可发现）才为 `true`；离线/未启用恒为 `false` | ✅ 已实现 |
| `adapter` | string | `disabled`（完全离线）或 `bridge`（经本机 ROS Bridge） | ✅ 已实现 |
| `state_text` | string \| null | Bridge 透传的 ROS 状态文本，格式 `running:inspect:<poi>` / `paused:inspect:<poi>` / `idle` / `done` / `stopped` / `aborted`；手动检查为 `running:manual:<poi>` / `running:manual:nav|intervene|settle|inspect|speak:<poi>`；离线时恒为 `null` | ✅ 已实现 |
| `detail` | string | 面向操作员的说明（离线原因、Bridge 错误等） | ✅ 已实现 |
| `checked_at` | string | 本次状态采样时间（ISO 8601，UTC） | ✅ 已实现 |

约束：

- 离线时**不得**出现任何伪造的 `state_text` 或 `online=true`。
- 前端进度/当前点位从 `state_text` 推导，属于展示逻辑，不写库。

## 2. 巡检轮次与状态转换

来源：`GET /api/status`（`current_round`）、`GET /api/rounds`、`GET /api/rounds/{round_id}`；
写入来自 `POST /api/ingest/rounds`、`/state`、`/finish`。

| 字段 | 类型 | 语义 | 状态 |
| --- | --- | --- | --- |
| `round_id` | string | 全局唯一轮次标识；Bridge 生成 `run-<16位十六进制>`，模拟数据为 `sim-<12位>` | ✅ 已实现 |
| `mode` | string | `inspection` / `manual` | ✅ 已实现 |
| `source` | string | `real`（Bridge 接入）/ `demo`（seed 脚本）/ `simulated`（开发模拟） | ✅ 已实现 |
| `is_demo` | bool | 由 `source=demo` 推导，`simulated` 时为 `false`（页面按 `source` 显示模拟） | ✅ 已实现 |
| `status` | string | `running` / `paused` / `completed` / `stopped` / `aborted` | ✅ 已实现 |
| `outcome` | string \| null | `normal` / `abnormal` / `uncertain`；未结束为 `null` | ✅ 已实现 |
| `operator_id` | string \| null | 发起人 | ✅ 已实现 |
| `ros_state` | string \| null | 最近一次 ROS 状态文本 | ✅ 已实现 |
| `summary` | string \| null | 结束摘要 | ✅ 已实现 |
| `error_message` | string \| null | 失败/中止原因 | ✅ 已实现 |
| `total_pois` | int \| null | 本轮计划点位总数；为 `null` 时前端不显示进度百分比 | ✅ 已实现 |
| `started_at` / `finished_at` | string \| null | 开始/结束时间（ISO 8601，UTC） | ✅ 已实现 |
| `recorded_count` | int | 已记录视觉结果数（不含跳过） | ✅ 已实现 |
| `processed_count` | int | 已处理点位数（含跳过），进度分子 | ✅ 已实现 |
| `abnormal_count` | int | `status_code=1` 的点位数 | ✅ 已实现 |

状态转换（Bridge `round_tracker`）：

```
idle ──running:*──▶ running ──paused:*──▶ paused ──running:*──▶ running
                      │                    │
                      └────done────────────┴──▶ completed
                      └────stopped─────────┴──▶ stopped
                      └────aborted─────────┴──▶ aborted
idle（有进行中轮次）──▶ stopped（ROS 状态回到 idle）
```

- 终态轮次再收到 `state` / `results` 写入时返回 **409**，不再修改。
- 同一 `round_id` 重复建轮幂等（201 新建 / 200 已存在），不会串轮。
- `outcome` 由点位结果推导：存在 `ABNORMAL` → `abnormal`；存在 `UNCERTAIN/TIMEOUT/NO_FRAME/NO_MODEL/ERROR` → `uncertain`；全部正常 → `normal`。

## 3. 单点视觉识别结果

来源：`round.results[]`；写入 `POST /api/ingest/rounds/{id}/results`；
机器人侧来源 `/fire_inspection/poi_result`（`PoiResult.msg`）。

| 字段 | 类型 | 语义 | 状态 |
| --- | --- | --- | --- |
| `poi` | string | 点位名，如 `POI_02` | ✅ 已实现 |
| `sequence` | int | 本轮内序号（从 0 递增） | ✅ 已实现 |
| `status_code` | int \| null | `0 NORMAL / 1 ABNORMAL / 2 UNCERTAIN / 3 TIMEOUT / 4 NO_FRAME / 5 NO_MODEL / 6 ERROR` | ✅ 已实现 |
| `status_name` | string \| null | 上述状态名，或跳过时的 `SKIPPED` | ✅ 已实现 |
| `skipped` | bool | 由控制指令产生的跳过；跳过**不写** `status_code` | ✅ 已实现 |
| `simulated` | bool | 结果是否来自模拟（页面显示「模拟」） | ✅ 已实现 |
| `detail` | string \| null | 原始说明文本，不重写、不猜测 | ✅ 已实现 |
| `detections` | array \| null | 由 `detections_json` 解析；解析失败为 `null` | ✅ 已实现 |
| `checked_at` | string \| null | 检测时间 | ✅ 已实现 |
| `duration_s` | float \| null | 单点耗时（秒） | ✅ 已实现 |
| `event_id` | string | Bridge 幂等键，按 `(round_id, event_id)` 唯一 | ✅ 已实现 |

约束：

- `NO_MODEL` / `NO_FRAME` 等**不得**被判为正常，`outcome` 记为 `uncertain`。
- 跳过不等于任何视觉结论；页面单独显示「已跳过」。
- 无结构化结果时绝不根据状态文本推断检测结论。
- 手动点名检查的正式结果写入独立的 `manual_inspection` 表，**不进入**本节
  `round.results[]`，统计也不与自动巡检混算。
- `PoiResult.msg` 当前不含任务标识（`round_id` / `manual_id`）。Bridge 只能依据
  「当前有效会话 + 点位」路由结果；若旧任务结果延迟到同点位新会话活动期内到达，
  仍存在残余误收风险。根治需经接口会签后为结果消息增加任务标识。

## 4. 防空警报检测事件 `alarm_detected`

来源：`POST /api/ingest/events`（令牌）、开发模拟入口；查询 `GET /api/events`。

| 字段 | 类型 | 语义 | 状态 |
| --- | --- | --- | --- |
| `event_id` | string | 全局唯一；重复上报不产生新记录 | 🔗 网页端约定 |
| `event_type` | string | 固定 `alarm_detected` | 🔗 网页端约定 |
| `timestamp` | string | 警报发生时间（ISO 8601）；缺省时后端用接收时间 | 🔗 网页端约定 |
| `source` | string | 产生方，建议 `alarm_monitor`（1–32 位字母数字/`_.-`） | 🔗 网页端约定 |
| `severity` | string | 固定 `critical`（建议） | 🔗 网页端约定 |
| `message` | string | 一句话说明，如「检测到防空警报」 | 🔗 网页端约定 |
| `details` | object \| null | 建议含 `zone` / `confidence` / `trigger` / `voice_broadcast` | ⏳ 待机器人端确认 |
| `round_id` | string \| null | 关联巡检轮次（警报可发生在巡检之外） | 🔗 网页端约定 |
| `poi` | string \| null | 关联点位 | 🔗 网页端约定 |
| `simulated` | bool | 模拟工具产生时为 `true` | ✅ 已实现 |
| `status` | string | `open / acknowledged / resolved`（网页处理状态） | ✅ 已实现 |

关键语义：

- 收到 `alarm_detected` **不代表已完成语音播报**；`details.voice_broadcast` 仅表示播报状态，
  当前约定值为 `"pending"`，播报结果必须由独立 `voice_broadcast` 事件表达。
- 事件不改变机器人 `online` 状态。

## 6. 巡检结束与失败事件

巡检结束仍以轮次终态表达（`round_finish` → `POST /api/ingest/rounds/{id}/finish`）：

| 字段 | 类型 | 语义 | 状态 |
| --- | --- | --- | --- |
| `status` | string | `completed` / `stopped` / `aborted` | ✅ 已实现 |
| `summary` | string \| null | 结束摘要 | ✅ 已实现 |
| `error_message` | string \| null | 失败原因 | ✅ 已实现 |
| `finished_at` | string \| null | 结束时间 | ✅ 已实现 |

独立「巡检失败事件」尚未定义。若机器人端需要独立事件，建议新增
`event_type = inspection_failed`（`⏳ 待机器人端确认`），并携带
`round_id` / `details.reason` / `details.stage`；在此之前网页端只用轮次
`status=aborted` + `error_message` 表达失败。

## 8. 控制命令与错误响应

来源：`POST /api/control`。

请求体：

| 字段 | 类型 | 语义 | 状态 |
| --- | --- | --- | --- |
| `cmd` | string | `start` / `pause` / `resume` / `skip` / `stop` / `manual` | ✅ 已实现 |
| `arg` | string | 点位参数；`manual` 必填，`skip` 可带且不得含空格；最长 64 | ✅ 已实现 |
| `operator_id` | string | 操作人；最长 64 | ✅ 已实现 |

响应体：

| 字段 | 类型 | 语义 | 状态 |
| --- | --- | --- | --- |
| `success` | bool | ROS 控制服务确认后才为 `true`；离线恒为 `false` | ✅ 已实现 |
| `message` | string | 结果说明 | ✅ 已实现 |
| `current_state` | string \| null | 控制后的 ROS 状态文本（若有） | ✅ 已实现 |
| `dispatched` | bool | `true` 仅表示 Bridge 已收到并确认 ROS 控制服务响应；离线恒为 `false` | ✅ 已实现 |

错误响应：

| HTTP | 场景 | 行为 | 状态 |
| --- | --- | --- | --- |
| 503 | 适配层未启用 / Bridge 不可达 / 后端未配置令牌 | `success=false`、`dispatched=false`，**不写库** | ✅ 已实现 |
| 504 | Bridge 已下发但控制服务无响应 | 结果未知，`dispatched=false` | ✅ 已实现 |
| 400 | `manual` 缺 `arg`，或 `arg` 含空格 | 明确拒绝 | ✅ 已实现 |
| 401 | `/api/ingest/*` 令牌缺失或错误 | 拒绝 | ✅ 已实现 |
| 409 | 终态轮次继续写入状态/结果 | 拒绝污染已结束记录 | ✅ 已实现 |
| 422 | 枚举/字段非法（如 `cmd=fly`、非法 `event_type`） | 参数校验失败 | ✅ 已实现 |
| 503 | 数据库损坏 / 不可用 | `{"detail": "数据库暂时不可用，请稍后重试。"}` | ✅ 已实现 |
